Same task, two controllers

Both controllers start from the same pose, with the same camera. PBVS (orange) controls the camera in 3-D: a straight camera path, but curved image paths. IBVS (green) controls the image: nearly straight image paths, but a 3-D path that nobody chose.

Try: large tilt: the PBVS points leave the image (bottom-right plot above 1), the IBVS points do not.

Calibration errors

The camera measures pixels. Both controllers convert them to normalized coordinates with the intrinsics they believe, \hat{\mathbf K}.

  • IBVS compares the current image with the desired image, taken by the same camera at the goal. Both go through the same \hat{\mathbf K}, so \ve=\mathbf 0 exactly at the true goal: the calibration error changes the path, not the result.
  • PBVS estimates the pose of the target with \hat{\mathbf K}. The estimate (dashed violet camera) is biased, and the camera stops where the estimate reads the desired pose.

Try: a focal length error of +10%: IBVS still reaches the goal, PBVS stops several centimetres away. Then add image noise: near the goal both cameras jitter by about the same amount (around 1 mm per pixel of noise here). Noise causes jitter; a calibration error causes a bias, and only PBVS suffers from it.

Complementary

Each scheme controls what the other leaves free: the 3-D path for PBVS, the image for IBVS. PBVS needs a correct pose, hence a good calibration and model; IBVS is robust to them, but can retreat or meet singularities. Hybrid schemes (2½-D visual servoing) combine the two.
